# 时间表悬浮按钮与智感握姿

2026-10-14

## 行为

- 晚课提示与回到本周使用同一个 `TimetableFloatingActions`。出现时从所在侧的屏幕外滑入，消失时沿同一侧水平滑出；退出完成前保留按钮内容。
- 入场保留 `interpolatingSpring(0, 1, 170, 17)`。退场使用该弹簧前 180ms 的归一化单调曲线，并通过 `customCurve` 明确在 180ms 完成；位移 84vp 覆盖 18vp 边距、48vp 按钮、16vp 材质外扩及 2vp 余量，不再等待离屏后的弹簧收敛。
- 原生退场完成回调直接提交另一侧入场，只有新边缘起点的必要一帧渲染，无额外等待定时器。不能给 `interpolatingSpring` 直接加 `duration` 来缩短其物理时长。
- 握持手改变时两个按钮成组先退出原侧，再从对侧进入；换边不改变垂直高度、顺序和间距。左右边距均为 18vp，按钮 48vp，两按钮顶边相差 60vp，底部继续避让原有 Dock 和系统安全区。
- 晚课提示显隐与回到本周的上下补位同时开始，不再串行等待补位弹簧。圆形按钮沿同步轨迹保持分离；滚动中反向显隐会立即更新原生动画目标，不等上一段结束。原有晚课判断及距离底部 64vp 的阈值不变。
- 正在按压任一按钮、切周、切页或显示底部弹层时延后换边。松手后仅保留 16ms 给点击和父状态更新；快速显隐和握姿变化合并到最新状态，旧动画完成回调及离页回调不能覆盖新一轮动画。

## 系统与机型

- 本项目最低系统仍为 HarmonyOS 6.1.0 / API 23，没有修改构建版本或签名。
- 使用 `motion.on('holdingHandChanged', callback)` 与 `ohos.permission.DETECT_GESTURE`，未申请活动运动用户权限。握持手接口本身从 API 20 提供。
- 同时检查系统 API 和 `SystemCapability.MultimodalAwareness.Motion`；不维护容易过时的机型白名单。是否实际支持最终由系统接口决定，801、权限拒绝或服务异常时按钮保持默认右侧并正常使用。
- 左右手结果稳定 80ms 后处理；双手、未握持、未知状态保留最后稳定位置，避免来回跳动。只在时间表页面有可用按钮时订阅；离页和无按钮时释放自己的回调及待执行任务。
- 官方文档以系统设置内是否存在“智感握姿”开关说明支持机型。模拟器不能替代支持机型上的真实握持识别验收。
